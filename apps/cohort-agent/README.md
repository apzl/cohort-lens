# CohortLens Agent

CohortLens Agent is a bounded, tool-using Flower AgentApp that investigates
released aggregate evidence from the CohortLens GDSC2 workflow. It uses Flower
Endeavor 1.0 (`flower-endeavor`) and never receives raw cell-line records,
design matrices, site-level estimates or node-local dataset paths.

The companion FederatedApp studies whether **BRAF p.V600E** is associated with
GDSC2 **PLX-4720** response (`LN_IC50`) across three deployment SuperNodes.

## Agent roles

- `investigator` runs only after a deterministic gate opens an investigation
  (cross-node disagreement with adequate support, or budget left after a
  follow-up). It runs a bounded plan, act, observe loop over six local,
  deterministic tools: `get_current_evidence`, `get_history`,
  `heterogeneity_diagnostics`, `list_actions`, `check_action` and
  `submit_proposal`. It chooses among a closed catalog of follow-ups
  (`LEAVE_ONE_SITE_OUT`, `STRATIFY_GDSC_LINEAGE`, `STOP_NO_FOLLOWUP`) and
  ends with one strictly validated, parent-bound proposal or a recorded
  failure. Steps, tool calls and invalid turns are capped.
- `reporter` makes one schema-validated call that summarises the released
  aggregates of a finished investigation.

Both roles receive only `InvestigationEvidence`: pooled estimates,
uncertainty, heterogeneity metrics, participation counts and the query budget
for every released round. Site-level results are stripped before the model is
called, and the tools compute only from that packet. The prompt describes the
role, constraints and tools; it does not contain the answer.

Tool calls use native Responses function calling or, by default, a
provider-agnostic protocol in which the model returns one strict JSON action
object per turn. Endeavor's native tool-calling support is unconfirmed; a
rejected native request falls back to the JSON protocol. Every tool call and
result is emitted as a structured run event and included, with the outcome,
in the framed `InvestigatorRecord` the operator collects.

Model output cannot authorise an analysis. An operator must approve a new
hash-bound analytics contract before any follow-up runs, and every site
re-checks it against its own allowlist and query budget.

Flower Runtime supplies the model endpoint and task token, so provider
credentials are not stored in the app bundle.

## Build and run

Preparation and orchestration are provided by the full
[CohortLens repository](https://github.com/apzl/cohort-lens). Build from its
root:

```shell
uv run python scripts/stage_apps.py
uv run flwr build --app apps/cohort-agent
```

Run with an aggregate-only investigator or reporter configuration generated by
the CohortLens command-line workflow (`cohortlens run-study --backend
supergrid` does this for every round):

```shell
uv run flwr run apps/cohort-agent supergrid \
  --federation @ACCOUNT/FEDERATION --run-config RUN_CONFIG.toml --stream
```

Run-config keys under `[agent]`: `mode`, `input`, `tool-protocol`
(`json` or `native`), `protocol-fallback`, `max-steps`, `max-tool-calls`,
`max-invalid-turns`, `max-output-tokens`.

The federated calculation itself is implemented by the separate
`apsal/cohortlens-analytics` Flower app. An AgentApp cannot start a federated
run, so the multi-round loop is driven by the operator. The AgentApp
investigates released evidence and proposes a constrained follow-up; it does
not access local data, run analyses, or decide that a scientific claim is
true.

The tool loop has been verified offline with fake model clients and a
scripted policy; it has not yet run against Endeavor. Earlier recorded
SuperGrid runs used a previous single-call investigator.

## Scope and limitations

This is a research demonstration over public, in-vitro cancer cell-line data,
not a patient study or clinical trial. Agent explanations are constrained but
still require human review. The workflow does not establish clinical benefit,
causality, or a validated treatment biomarker.
