How it works

The question travels. The records stay where they are.

Three labs hold data they cannot pool. CohortLens sends each of them the same pre-approved statistical question, lets each one answer it on its own rows, and brings back an effect, its standard error and a count. A coordinator combines the three answers and checks whether the sites agree.

  • Personal project
  • Emulated three-site federation
  • Public GDSC2 cancer cell-line data, not patients
  • Flower 1.37 SuperGrid, three SuperNodes

Step by step

What each step does

Ten steps from raw files to a report. Each card says what crosses the wire and where the code lives. Press a number to replay that step in the diagram.

Prepare the site data

The operator reads the GDSC2 response workbook, the Cell Model Passports model list and the driver-mutation summary, keeps PLX-4720, and splits cell lines into three sites by sha256(SANGER_MODEL_ID) % 3. The split never looks at drug response. Each site gets a numeric matrix with no model IDs in it.

Crosses the wire nothing, this runs on the data side
cohortlens_shared/gdsc.pyprepare_gdsc_snapshots

Write the contract, approve its hash

The question is a frozen contract: compound, variant, outcome, covariates, estimator, release policy. Its canonical JSON is hashed with SHA-256, and a time-limited approval is bound to that hash. Change one field and the approval no longer matches.

Produces AnalysisContract Approval
cohortlens_shared/schemas.pydefault_gdsc_contract · contract_digest

Submit the run

The contract and approval go to Flower SuperGrid as a run config. The ServerApp refuses leftover placeholders, checks the approval (hash, study, analysis, expiry) and waits for three SuperNodes with a bounded deadline.

Crosses the wire run-config TOML with the contract and approval inlined, no file paths
cohortlens_analytics/server_app.py

Preflight at every site

Each node checks the request for itself. It re-validates the approval, compares the analysis against a hard-coded allowlist, and confirms it has enough rows in each group. It answers READY or one of seven refusal codes.

Crosses the wire StudyPreflightRequest → PreflightReply
cohortlens_analytics/client_app.pyhandle_preflight

Local regression

Only READY nodes get the question. Each one loads its own matrix, fits ordinary least squares, and computes an HC3 robust standard error for the BRAF V600E coefficient. Rows and design matrices never leave the node.

Crosses the wire AssociationRequest → AssociationReply with β, SE, N and the contract hash
client_app.py · handle_associationstatistics.py · fit_genotype_ols_hc3

Validate and pool

The ServerApp ties every reply to its node, study, query and contract hash. A missing, invalid or duplicate reply is recorded as such, never silently dropped. With two or more estimates it runs an inverse-variance fixed-effect meta-analysis and reports β, a 95% interval, Cochran Q and I².

Releases AssociationResult as one framed log line
server_app.py · run_phase1statistics.py · fixed_effect_meta

Collect, then gate

The operator pulls the run log and accepts exactly one schema-valid result frame for the expected study and hash. A plain function then decides what happens next: stop, finish, or investigate. No model is involved in that decision.

Produces InvestigationDecision
cohortlens_operator/result_frames.pyschemas.py · investigation_decision_from_result

Report, or ask for a proposal

Site-level results are stripped first. If the sites agree, one LLM call writes a short report. If they disagree, one LLM call receives the pooled numbers and must return a proposal in a fixed schema: stratify by melanoma versus other lineages. One repair retry, then a hard failure.

Crosses the wire AgentEvidence → ReporterOutput or FollowUpProposal
cohortlens_agent/agent_app.py

A human approves the follow-up

The proposal authorizes nothing. The operator compiles the only permitted follow-up contract, tied to the hash of the first result, and signs a fresh approval for its new hash. Without that, no second run exists.

Produces a new AnalysisContract + Approval
schemas.py · compile_stratified_followup

Stratified second run and report

The same preflight, regression and pooling run once per stratum: skcm and non_skcm. Each node selects its rows locally and refits. The result is marked exploratory, and a final LLM call summarizes it from aggregates only.

Releases Phase2AssociationResult → ReporterOutput
server_app.py · run_phase2statistics.py · context_stratum
Disclosure

Who sees what

The data gets smaller at every hop. Three lines are enforced in code, and each party only receives what is listed in its column.

SuperNode

one per site, holds the data

  • Cell-line rows and outcomes
  • Its own β, SE, N
  • Contract and approval

Coordinator

ServerApp and operator

  • Cell-line rows and outcomes
  • Each site's β, SE, N and status
  • Pooled β, 95% CI, I²

LLM call

Flower Endeavor, one call per run

  • Cell-line rows and outcomes
  • Each site's β, SE, N
  • Pooled β, 95% CI, I²
  • Hash of the result, allowed actions

Human operator

the only one who can authorize

  • The LLM's proposal, schema-checked
  • The new contract and its hash
  • Decides whether a second run happens

Rows stay on the node

Only an allowlisted AssociationReply leaves a site. Payloads are capped at 64 KiB.

The LLM gets aggregates

AgentEvidence has no field for site-level results, so they cannot be passed along by mistake.

A proposal is not permission

A second run needs a new contract hash and a fresh, expiring approval from a person.

The decision

A gate made of plain code

I² measures how much the sites disagree beyond chance. The rule that reads it is a few lines of ordinary code with three outcomes. Move the slider to see it flip at 0.50.

Technical details

How it is built

Seven decisions that shape the code.

Hash-bound, frozen contracts

Every schema is a frozen Pydantic model that forbids extra fields and NaN. The contract's canonical JSON (sorted keys, compact) is hashed with SHA-256, and the approval carries that hash plus a timezone-aware expiry.

Sites re-check everything

A valid approval is not enough. Each node validates it again and compares the analysis to a closed allowlist, then enforces minimum sample size and group support before computing anything.

OLS-HC3 in plain NumPy

The regression and its heteroskedasticity-robust standard error are written by hand, so the deployed bundle needs neither SciPy nor statsmodels. Tests match statsmodels 0.14.5 to a relative tolerance of 1e-10.

Fixed-effect meta-analysis

Site estimates are combined by inverse-variance weighting, with a 95% interval, Cochran Q and I². Missing, invalid and duplicate replies are tracked as explicit states, so a partial result is reported as partial.

A closed-world LLM step

The model gets no tools. It makes a single call, sees aggregates, and must answer in a strict schema with literal-typed actions. The output is checked against the study, analysis and parent hash. One repair attempt, then the run fails.

Results travel as log frames

Each app prints one framed line, COHORTLENS_RESULT_V1 {json}. The operator extracts exactly one valid frame from the run log. Identical replays are accepted, conflicting frames fail.

Two bundles, one bridge

A Flower App Bundle holds either a ServerApp with its ClientApp or an AgentApp, not all three. So analytics and the LLM step ship separately, and the human operator is the only link between them.

Limits

What this is not

The project demonstrates a workflow. It does not make a scientific or a privacy claim beyond what is listed here.

About the federation

  • The federation is emulated. The three sites are hash partitions of one public dataset, not independent labs.
  • No secure aggregation or differential privacy. Rows stay local, but that is not a confidentiality guarantee.
  • The coordinator sees site summaries. Result frames are also visible to anyone who can read the run logs.
  • A dishonest site would go unnoticed. Hashes and approvals prevent protocol mistakes. They do not prove a site computed honestly.

About the science and the LLM

  • Cell lines, not patients. The data is public in-vitro drug-response measurements.
  • Associations, not clinical findings. Nothing here shows causality, clinical benefit or a validated biomarker.
  • The LLM step is one schema-bounded call. It has no tools and almost no latitude. It is not a tool-using agent.
  • The follow-up is exploratory. It reuses the same records, so it is not a replication.
